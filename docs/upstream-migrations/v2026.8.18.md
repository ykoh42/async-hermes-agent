# Upstream v2026.8.18 migration manifest

Baseline: `v2026.8.16.2` → `v2026.8.18` (Python `0.20.3` → `0.20.4`).
The async distribution is `0.20.4.1`.

## Retained and ported

- `e99743500` — v25 system-prompt dedupe now degrades gracefully under
  SQLite contention. The async schema path keeps the same transaction and
  skips only the contended row; a later initialization retries it.
- `6e22d2658` — project-local skills use the existing skills-guard scanner.
  The async fork awaits the native scanner and keeps the cache under the
  active Hermes home; scanner failures quarantine the skill.
- `b95ec1cb5` — delegation control uses durable parent session ownership and
  process notifications retain child attribution. The async fork awaits
  session-lineage resolution rather than calling a coroutine synchronously.
- `aa8ceed4b` — a stale holographic memory holder cannot evict a fresh shared
  registry entry. The identity check is unchanged; the close lifecycle remains
  native async.
- `833f0e2ac`, `eaa3c72c3`, `f2f6dce78`, `d4658ee6d`, `24545418e` — bundled
  Meta Model API profile, exact `api.meta.ai` Responses routing, 24-hour prompt
  cache retention, reasoning-effort mapping, and provider behavior tests.

## Removed or out of scope

- Desktop, gateway, Bot Mode, cron, peer, update, dashboard, and Nemo Relay
  changes are removed product surfaces in this distribution.
- `tools/skillevaluator_scan.py` and its tests belong to the removed Skills Hub
  CLI install path. Retained skill listing/viewing uses the existing async
  `tools.skills_guard` scanner instead.
- `plugins/plugin_storage.py` and its tests add a synchronous plugin SQLite
  API with no retained consumer in this library; adding it would violate the
  native-async boundary and expand the public surface.

## Verification

The changed retained behavior is covered by the copied/adapted tests in
`tests/agent/`, `tests/providers/`, `tests/hermes_cli/`,
`tests/plugins/memory/`, `tests/state/`, and `tests/tools/`. Unclassified
retained hunks: **0**. Physical PostgreSQL behavior is checked by the existing
backend differential suite; this upstream release adds no PostgreSQL schema
change.
